# 画像スロットと本ファイルの食い違い事故

この文書は、Claude Designの編集環境で起きた画像保存事故の履歴である。現行の公開画像は、リポジトリにある `assets/photos/*.webp` とHTMLの参照を正本とする。ここに記録するブラウザ操作用ツール名は当時の復旧手段であり、現在も利用できるとは限らない。

## 何が起きたか

`image-slot.js` は、差し替えた画像をブラウザの `localStorage` と `assets/photos/*.webp` の両方へ保存していた。本ファイル側の書き込みが、環境要因でエラーを出さず静かに失敗することがあった。

本ファイルの保存に失敗しても、ブラウザ内のプレビューは `localStorage` の画像を表示するため、編集画面では正しく見え続けた。その結果、ダウンロードまたは公開したファイルだけが古い画像のままになる食い違いが発生した。2026年7月20日に複数のスロットで実際に確認した。

## 当時の検出方法

公開またはダウンロード提供の前に、ブラウザ内の画像と `assets/photos/*.webp` を突合した。

1. 各スロットについて、`localStorage` の画像と `fetch` した本ファイルを取得する。
2. それぞれを小さく縮小し、輝度シグネチャを作る。
3. シグネチャの差が大きいスロットだけを食い違いとして扱う。
4. 一括処理はタイムアウトするため、複数の小さなバッチに分ける。

この検査は画像の完全一致ではなく、編集画面と本ファイルの大きな相違を見つけるための実用的な比較だった。

## 当時の復旧方法

食い違いが見つかった画像は、ブラウザに表示されている画像をスナップショットとしてプロジェクトへ書き出し、WebPへ変換して `assets/photos/<slot-id>.webp` を上書きした。当時の環境には、`localStorage` のデータをそのままプロジェクトファイルへ保存する経路が無かったため、この方法を使った。

## 再発防止

- 編集画面で正しく見えることを、公開ファイルへ保存できた証拠にしない。
- 差し替え後は、HTMLの `src`、本体画像、必要なレスポンシブ画像をリポジトリ側で確認する。
- ダウンロード提供前と公開前に、少なくとも一度はブラウザ表示と本ファイルを突合する。
- Claude Designとコード編集を並行するときは、どちらを画像の正本にするかを切り替え時点で明確にする。
- 公開後はキャッシュを避けたURLで、実際に配信された画像を確認する。

## 移管元の具体的な検出・復旧記録

当時の検出では、各スロットのlocalStorage画像とfetchした本ファイルをそれぞれ8×8へ縮小し、輝度シグネチャを比較した。全スロットを一度に処理するとタイムアウトしたため、10〜15件ずつに分けた。これは完全一致検査ではなく、大きな食い違いだけを発見する方法だった。

食い違いが見つかったスロットは、当時の編集環境の `snapshot_element` で表示中の画像をPNGとして書き出し、WebPへ変換して `assets/photos/<id>.webp` を上書きした。localStorageのデータを直接プロジェクトファイルへ書く経路が無かったためである。これらのツール名は履歴であり、現在の環境では同じ機能を持つ手段を選ぶ。

最低限の実施時点は「ダウンロードを渡す直前」と「公開直前」だった。現行では、ブラウザ表示、本ファイル、HTMLの `src`／crop属性、本番配信を順に突合する。

## 移管元の原文

次は移管前の事故記録を改変せず引用したもの。件数と当時のツール名は歴史値であり、現行手順は前節を使う。

> ## 画像の「ブラウザ内と本ファイルの食い違い」対策（2026-07-20 発覚・再発防止ルール）
>
> **何が起きたか**：image-slot.js は画像を localStorage と `assets/photos/*.webp`（本ファイル）の両方に保存するが、本ファイル側の書き込みが環境要因で**エラーを出さず静かに失敗**することがある。その間もブラウザのプレビューは localStorage から表示するので正しく見え続け、誰も気づけない。結果、ダウンロード・公開時に本ファイル側だけ古い写真のまま、という食い違いが起きた（2026-07-20、5スロット分で発生）。
>
> **再発防止ルール（ダウンロード提供・公開前は必ず実施）**：
> - ユーザーへのダウンロード提供や公開作業の前に、localStorage の画像と `assets/photos/*.webp` を突合するチェックを走らせる。方法：`eval_js_user_view` で各スロットの localStorage 画像と、fetch で取得した本ファイルをそれぞれ 8×8 縮小→輝度シグネチャ化して比較（`diff` が大きいものだけ食い違い＝要再焼き込み）。全スロット一括だとタイムアウトするので10〜15件ずつバッチ分割する。
> - 食い違いが見つかったスロットは、`snapshot_element` でブラウザ表示中の画像をPNGとして直接プロジェクトへ書き出し→run_script で webp 変換→`assets/photos/<id>.webp` を上書き（localStorage の中身を直接ファイル化する書き込み経路がこの環境には無いため、この経路を使う）。
> - 差し替え作業のたびに実施するのが理想だが、最低限「ダウンロードを渡す直前」「公開直前」には必ず1回実施する。
