# 法令・料金・公開情報の変更

## 正本と確認順

外部向けの事務所名、代表、所在地、連絡先、営業時間、対応範囲、サービス、料金、公開コピーは、記憶や過去の指示書から転記しない。公開HP基準の事業プロフィールを参照し、変更直前に `origin/main` の現行実装と本番HPを突合する。NAPの現況は `scripts/check-structured-data.mjs` の検査対象を正本とする。

制度、料率、助成金、統計、製品料金・機能は、次の順で確認する。

1. 対象年度の官公庁・制度運営者・製品公式情報
2. 実際の見積書、通知、様式、実機結果
3. 改訂日と正本表示が明確な内部資料
4. 現行HP本文

過去のプロンプト、バックアップ、事故記録は現行事実の根拠にしない。

## 法令・制度の書き方

- 対象年度、施行日、基準日、対象地域、計算前提を明記する。
- 対象者・対象外、原則・例外、義務・努力義務、確定事項・審議中を区別する。
- 金額や料率は計算過程と端数処理を確認し、事例の前提を省略しない。
- 解釈が分かれる論点は、根拠、複数の解釈、実務リスク、判断材料を示す。
- 強い言い切りだけを理由に修正しない。一次資料が断定している事項は明確に書き、根拠が不足する部分だけを限定する。
- 読者が実際に何を、いつまでに、どの順番で行うかまで示す。

## 「診断」の使用方針

- サービス名・営業表現としての「診断」は使わない。
- 法令上の正式名称「健康診断」「特定健康診査」等はそのまま使う。
- 個人の病状を事務所が判断するような表現は使わない。

## 助成金

- 「受給できます」と書かない。受給保証ではない旨を残す。
- 事前の計画・認定・届出が必要な制度では、その要件を目立つ位置に置く。
- 対象事業主・労働者・経費、実施期限、申請期限、賃金・雇用条件、証憑、併給調整を確認する。
- 規程を作るだけで支給されるように見せない。不支給、返還、不正受給のリスクを隠さない。
- 金額は対象年度と試算条件を示し、毎年度変わる数値を恒久情報として固定しない。

## 事務所実績・資格・比較表現

- 勤務先での経験を、開業後の事務所受任実績として表示しない。
- 架空の顧客事例・お客様の声・削減事例を実例として掲載しない。
- 根拠のないNo.1、受賞、認証、登録、資格、提携を掲載しない。
- 登録番号は取得後の実番号だけを掲載し、プレースホルダを公開しない。
- 匿名事例を使う場合も、実在事例か想定例かを明示する。

## 料金・サービス範囲

- 料金は本番の料金ページと矛盾させない。税区分、対象人数、基本料金、追加料金、含む業務、含まない業務、見積条件を確認する。
- 「いつでも」「何度でも」「必ず」など、提供上限が曖昧な約束をしない。
- 無料相談で行うこと・行わないこと、追加料金が生じる条件を事前に示す。
- 未確認の製品料金・機能、導入効果、削減率を断定しない。効果は顧客の実測値を基に算定する。

## 税務・他士業との業際

年末調整は、社労士事務所のサービスとして単独完結するように表示しない。資料整理と給与データ準備、税理士との連携として扱う。税務判断・税務書類作成、法律判断など、他士業の独占業務を事務所業務と誤認させない。

## 構造化データと表示本文

- JSON-LDのFAQ、サービス、NAP、料金等は見える本文と一致させる。
- FAQは表示本文を正本とし、`scripts/sync-structured-data.mjs` と `scripts/check-structured-data.mjs` で同期・検査する。
- 公開日・更新日は実質的な更新に合わせ、SEO目的だけで変更しない。
- 未確認の公開事実を構造化データだけへ先に追加しない。

## 所有者確認の現況

- GoatCounter：アカウント登録済み。実アクセスの計測確認は確認待ち
- 社労士登録番号：未確定。確定前は掲載しない
- 採用ページの給与・勤務地：所有者確認済み
- FormSubmit：現行送信先で受信確認済み

未確認事項は推測で掲載せず、確認待ちとして扱う。

## 公開前確認

```bash
node scripts/sync-structured-data.mjs --check
node scripts/check-structured-data.mjs
node scripts/preflight.mjs
```

法令・数値を変えた場合は公式一次資料のURL、対象年度、確認日を作業記録へ残す。本番公開後は変更したページの表示本文と構造化データを再確認する。
